# GPT(OpenAI API) OCR 테스트

로컬 모델 GravityOCR-KO의 결과를 GPT로 보정하는 방법과, GPT만으로 OCR하는 방법을 손글씨와 영수증으로 측정했습니다. 측정 기간은 2026-11-10 ~ 2026-11-11입니다.

## 요약

- **손글씨:** GPT 단독 OCR이 가장 정확합니다. `gpt-6.1-terra`의 오류율(CER)은 0.06%이고, GravityOCR-KO는 12.08%입니다.
- **영수증:** `gpt-6.1-terra`로 항목을 추출하면 금액과 거래 일시를 20장 모두 정확히 뽑습니다.
- **추론 기능:** `gpt-6.1-terra`에서 추론을 꺼도(`effort: none`) 정확도는 사실상 같고, 속도는 최대 1.7배 빨라지며 출력 토큰은 절반으로 줄어듭니다.
- 손글씨용 `handwriting.py`와 영수증용 `receipt.py`를 별도 모듈로 만들었습니다. 두 모듈의 기본 모델은 `gpt-6.1-terra`입니다.
- **외부 전송:** 이미지가 OpenAI로 전송됩니다. 영수증 20장은 사용자가 "공개된 정보"라고 확인한 뒤에 전송했습니다.

## 1. 테스트 환경과 데이터

| 항목 | 내용 |
|---|---|
| API | OpenAI Responses API, `openai` 3.49.0, 이미지는 base64 data URL로 보내고 `detail: "high"`를 지정 |
| API 키 | `.env`의 `OPENAI_API_KEY` (git 제외, 권한 600) |
| 손글씨 데이터 | 노트 손글씨 사진 18장, 총 3,179자 (`samples/handwriting/`, git 제외) |
| 영수증 데이터 | 운영 서버에서 가져온 실제 영수증 20장 (`samples/real/`, git 제외) |
| 손글씨 지표 | 글자 단위 오류율(CER), 띄어쓰기는 무시, NFC 정규화 |
| 영수증 지표 | ① OCR 텍스트 안에 정답 값이 들어 있는지(`bench.py`) ② 추출한 항목이 정답과 정확히 같은지(`receipt.py --eval`) |

**정답 데이터의 한계:**
- 손글씨 정답은 Claude가 이미지를 읽어 만들었습니다. 그래서 대형 모델끼리 같은 글자를 똑같이 잘못 읽으면 그 오류는 수치에 잡히지 않습니다.
- 측정하는 도중에 06번 정답의 "27."이 실제로는 "21."임을 확인하고 고쳤습니다. 이 문서의 수치는 모두 고친 정답을 기준으로 다시 계산한 것입니다.
- 오류율이 0.1% 아래로 내려가면, 정답에 남아 있을지 모르는 오류가 모델 사이의 차이보다 클 수 있습니다.

## 2. 손글씨: GravityOCR 결과를 GPT로 보정

GravityOCR-KO의 OCR 결과를 `gpt-5.4-mini`에 보내 오탈자만 고치게 했습니다(`python llm_fix.py text|image <model>`). 지시문에는 다음 원칙을 넣었습니다.
- 오탈자만 고친다.
- 문장을 바꿔 쓰거나 내용을 더하지 않는다.
- 줄 구조를 유지한다.
- 숫자는 근거가 없으면 바꾸지 않는다.

| 방식 | CER | 1장당 추가 시간 | 18장 토큰 (입력 / 출력) |
|---|---|---|---|
| 보정 전 (GravityOCR-KO) | 12.08% | – | – |
| 텍스트만 보내 보정 | 6.67% | 약 2초 | 4,733 / 2,583 |
| 이미지와 텍스트를 함께 보내 보정 | 1.82% | 약 6초 | 58,103 / 2,595 |

- 보정한 뒤 오류율이 오른 페이지는 한 장도 없었습니다. 따라서 GPT가 없는 내용을 지어내 결과를 망치는 현상은 이번 데이터에서 나타나지 않았습니다.
- 텍스트만 보낼 때는 사랑→사람처럼 문맥으로 고칠 수 있는 오류만 고쳐집니다. 깊이→같이처럼 두 단어가 모두 문맥에 맞는 오류는 이미지가 있어야 고칠 수 있습니다.

## 3. 손글씨: GPT 단독 OCR

GravityOCR 없이 이미지만 보내 OCR했습니다(`python llm_fix.py ocr <model>`).

| 모델 | CER | 틀린 글자 수 | 1장당 시간 | 18장 출력 토큰 |
|---|---|---|---|---|
| **gpt-6.1-sol** | **0.03%** | 1 | 9.0초 | 5,376 |
| **gpt-6.1-terra** | **0.06%** | 2 | 8.1초 | 5,618 |
| gpt-6.1-terra (추론 끔) | 0.13% | 4 | 7.2초 | 2,596 |
| gpt-6-astra | 0.13% | 4 | 15.9초 | 4,611 |
| gpt-5.5 | 0.41% | 13 | 약 12초 | 11,128 |
| gpt-6-sol | 0.57% | 18 | 8.5초 | 8,872 |
| gpt-6-luna | 0.57% | 18 | 11.0초 | 12,616 |
| gpt-5.6-sol | 0.75% | 24 | 10.2초 | 10,076 |
| gpt-5.6-terra | 1.51% | 48 | 8.3초 | 7,950 |
| gpt-5.6-luna | 1.64% | 52 | 9.3초 | 10,041 |
| gpt-5.4-mini | 3.21% | 102 | 약 6초 | 2,605 |

- 입력 토큰은 18장 기준 약 53,900개로 모든 모델이 같습니다. 출력 토큰에는 추론 토큰이 포함됩니다.
- `gpt-6.1-luna`는 계정의 모델 목록에 없어서 측정하지 못했습니다.
- `gpt-6.1-sol`이 틀린 1자는 09번 페이지 번호입니다. 3과 2를 덧쓴 듯한 글자여서 사람이 봐도 34인지 24인지 판단하기 어렵습니다.
- `gpt-6.1-terra`는 "보라"를 "보자"로, "불만"을 "불안"으로 읽었습니다.
- 두 6.1 모델의 차이는 1~2자이므로 이 데이터로는 우열을 가릴 수 없습니다.
- **판단:** 손글씨는 GPT 단독 OCR로 처리합니다. 추론을 끌 수 있고 영수증에서도 가장 좋았던 `gpt-6.1-terra`를 기본 모델로 정했습니다.

## 4. 영수증: OCR 텍스트에 정답 값이 들어 있는지

이 측정은 `bench.py`와 같은 방식입니다. OCR로 얻은 텍스트 안에 정답 값이 들어 있는지를 확인합니다(`python bench.py samples/real <model>`).

| 엔진 | 금액 | 날짜 | 시각 | 가게명 정확 일치 | 가게명 부분 일치 | 1장당 시간 |
|---|---|---|---|---|---|---|
| GravityOCR-KO (RTX 4090) | 20 | 20 | 20 | 8 | 12 | 약 3초 |
| gpt-5.4-mini | 17 | 20 | 20 | 8 | 16 | 6.4초 |
| gpt-6.1-sol | 19 | 18 | 20 | 17 | 19 | 20.9초 |
| **gpt-6.1-terra** | **20** | **20** | **20** | **18** | 19 | 14.7초 |
| gpt-6.1-terra (추론 끔) | 19 | 20 | 20 | 17 | 18 | **8.6초** |
| gpt-6-astra | 19 | 19 | 20 | 18 | 19 | 33.8초 |

- GPT는 가게명을 GravityOCR보다 훨씬 잘 읽습니다(정확 일치 8 → 18).
- 추론을 끈 `gpt-6.1-terra`는 금액 1건(43,900원)을 44,700원으로 옮겨 적었습니다. 그런데 같은 영수증을 `receipt.py`로 추출하면 금액을 정확히 뽑습니다. 그래서 추론을 꺼서 생긴 오류라기보다 실행할 때마다 결과가 흔들리는 것으로 봅니다.

## 5. 영수증: 항목 추출 (`receipt.py`)

`gpt-6.1-terra`에게 JSON 스키마(structured output)를 주고 가게명, 금액, 거래 일시, 분류를 바로 추출하게 했습니다(`python receipt.py --eval`). 각 항목이 정답과 정확히 같은 장수를 셌습니다.

| 설정 | 금액 | 거래 일시(분 단위) | 가게명 | 분류 |
|---|---|---|---|---|
| 처음 지시문 | 20 | 20 | 16 | 16 |
| 분류 기준과 택시 규칙 추가 | 20 | 20 | 16 | 17 |
| 분류 기준과 택시 규칙 추가, 추론 끔 | 20 | 20 | 16 | 17 |

- 가게명은 띄어쓰기와 문장부호를 무시하고 비교했습니다.
- 지시문에 분류 기준(식대: 음식점·카페·편의점·제과점, 교통비: 택시·버스·철도·주유·주차)과 "택시는 운수회사명" 규칙을 추가한 뒤, 편의점(CU) 영수증을 식대로 맞혔습니다.

**틀린 항목 분석:**

| 영수증 | 항목 | 정답 | 추출 결과 | 원인 |
|---|---|---|---|---|
| 택시 영수증 | 가게명 | 중앙교통(주) | null | 규칙을 추가해도 운수회사명을 비워 둡니다 |
| 1774998315407 | 가게명, 분류 | 호호, 식대 | 오오, 기타 | 글자를 잘못 읽었고, 이름만으로는 업종을 알 수 없습니다 |
| 1774998315466 | 가게명 | 구로전화국사거리점(버거킹) | 구로전화국사거리점 | 정답의 표기 방식이 독특합니다 |
| 1774998315554 | 가게명 | 옹심이메밀칼국수 | 웅심이메밀칼국수 (처음 지시문으로 실행했을 때) | 글자를 잘못 읽었습니다 |
| 1774998314894 | 가게명 | 비 에이글 (Be, agle) | 비 에이글 | 실행할 때마다 괄호 부분이 붙거나 빠집니다 |
| 우리집 2장 | 분류 | 식대 | 기타 | 이름만으로는 업종을 알 수 없습니다 |

- 정산에 중요한 금액과 거래 일시는 모두 정확합니다.
- 더 정확하게 하려고 지시문을 계속 고치면 20장에만 맞춘 조정이 되기 쉬워서, 이 시점에서 멈췄습니다.
- 실제 데이터에서 영수증 대부분이 식대라면, 분류를 알 수 없을 때 기본값을 식대로 두는 것을 검토합니다.

## 6. 추론 기능 끄기

| 모델 | 추론을 끄는 값(`none`) 지원 여부 |
|---|---|
| gpt-6.1-terra | 지원 |
| gpt-6.1-sol, gpt-6-astra | 지원하지 않음 (가장 낮은 값이 `low`) |

| 측정 항목 (gpt-6.1-terra) | 추론 켬 (기본값) | 추론 끔 |
|---|---|---|
| 손글씨 CER | 0.06% | 0.13% |
| 손글씨 1장당 시간 | 8.1초 | 7.2초 |
| 손글씨 18장 출력 토큰 | 5,618 | 2,596 |
| 영수증 텍스트 1장당 시간 | 14.7초 | 8.6초 |
| `receipt.py` 항목 정확도 | 20 / 20 / 16 / 17 | 20 / 20 / 16 / 17 |

- **판단:** 정확도 차이는 무시할 수 있는 수준이고 속도와 비용은 나아지므로, 추론을 끄는 설정을 권장합니다.
- 추론 설정은 환경 변수 `GPT_REASONING=none`으로 켜고 끕니다. 지정하지 않으면 모델의 기본 설정(추론 켬)으로 동작합니다.

## 7. 모듈 구성과 사용법

| 파일 | 하는 일 |
|---|---|
| `gpt.py` | OpenAI 연결, 이미지 변환, 텍스트 OCR `ocr(path, model)`, 추론 설정(`GPT_REASONING`) |
| `handwriting.py` | `recognize(path) -> str`: 손글씨를 텍스트로 옮깁니다. 모델은 `HANDWRITING_MODEL`로 지정하고 기본값은 `gpt-6.1-terra`입니다 |
| `receipt.py` | `recognize(path) -> dict`: `store_name`, `total_amount`, `transaction_datetime`, `category`를 돌려줍니다. 읽을 수 없는 값은 `None`입니다. 모델은 `RECEIPT_MODEL`로 지정하고 기본값은 `gpt-6.1-terra`입니다 |
| `llm_fix.py` | 손글씨 실험 스크립트입니다. 모드는 `text`, `image`, `ocr` 세 가지입니다 |
| `bench.py` | 영수증 텍스트 벤치마크입니다. 두 번째 인자로 GPT 모델을 주면 GPT로 OCR합니다 |

```bash
python handwriting.py <이미지>
python receipt.py <이미지>                  # 항목을 JSON으로 출력
python receipt.py --eval                    # 정답 데이터와 비교
GPT_REASONING=none python receipt.py --eval # 추론을 끄고 평가
python llm_fix.py ocr gpt-6.1-terra         # 손글씨 CER 측정
python bench.py samples/real gpt-6.1-terra  # 영수증 텍스트 측정
```

## 8. 남은 과제

1. 손글씨 정답을 사람이 검수합니다. 지금 수치는 Claude가 만든 정답을 기준으로 합니다.
2. 앱에서 문서 종류에 따라 엔진을 고르게 합니다. 예를 들어 손글씨와 영수증은 GPT, 오프라인 처리나 대량 처리에는 GravityOCR을 씁니다.
3. 실제 단가를 확인하고 장당 비용을 계산합니다. 이 문서에는 토큰 수만 기록했습니다.
4. 실제가 아닌 영수증 데이터로 지시문 조정 결과를 검증합니다. 지금은 20장에만 맞췄을 위험이 있습니다.
